# Feature Brief / Execution packet

## Goal
Добавить включение и выключение автоподключения: все плееры или выбранные пользователем сайты, например только YouTube.

## Existing Context
MV3 0.1.1, tabCapture → offscreen → AudioWorklet. Ручной запуск, общий DSP, 18 тестов. Исходный запрос сохранён: «сделай кнопку включения и выключения автоподключения ко всем плеерам и отдельно функцию к плеерам которые выберет пользователь, например только на ютуб».

## Explicit Requirements
- Переключатель автоподключения.
- Режим всех сайтов с плеерами и отдельный режим списка выбранных сайтов.
- Пользователь может оставить только YouTube и редактировать список.

## Assumptions / Technical Constraints
- Список задаётся доменами; включает их поддомены, а не идентификаторы DOM-плееров.
- По умолчанию автоподключение выключено, выбранный список youtube.com / youtu.be.
- chrome.tabCapture требует вызова расширения пользователем в каждой новой вкладке. Нельзя обещать автономный запуск во всех новых вкладках; UI прямо сообщает это ограничение. Открытие popup запускает подходящую вкладку автоматически, далее автоматические события пробуют повторный запуск в пределах разрешения Chrome.
- Новый tabs permission нужен для классификации URL и получения audible-состояния фоновых вкладок. Не добавляются host_permissions или чтение DOM.
- Переключатель выключает автоматически начатые сессии, но сохраняет отдельно начатые вручную. Ручная остановка приостанавливает авто для данной вкладки до смены сайта или явного включения.

## User Flows
1. Включить авто и выбрать все сайты; текущая вкладка запускается сразу, звучащие вкладки запускаются при наличии разрешения, остальные отмечаются как требующие открытия расширения.
2. Выбрать только выбранные сайты; оставить YouTube, добавить домен/URL или текущий сайт, удалить ненужные.
3. Отключить авто: автоматические сессии завершаются; ручная кнопка остаётся доступна.

## In / Out of Scope
Входят фильтрация доменов, сохранение, сессии, интерфейс и обработка событий. Автономный обход ограничения Chrome, content-script Web Audio с риском тишины при CORS, изменение DSP, микрофон и публикация вне задачи.

## Technical Plan / Ordered Tasks
1. shared/automatic.js: нормализация доменов и политика выбора.
2. automatic.js и background.js: очередь, сохранение local/session, lifecycle и автоматический запуск; offscreen.js: метаданные automatic и список сессий.
3. popup: переключатель, область применения, список сайтов, текущий сайт, состояние паузы/разрешения Chrome.
4. Тесты фильтрации, запрещённого старта, ручной паузы, режима off, смены выбранных сайтов, перезапуска worker и автоматических событий.
5. Проверки, версия 0.2.0, README и ZIP.

## Failure Cases / Definition of Done
Нет двойного захвата, ручная остановка не отменяется автоматикой, ошибки без granted tabCapture не зацикливаются, metadata переживает сон worker. Включение/выключение влияет только на auto-owned сессии. Неверные домены отвергаются. На новой вкладке без разрешения UI говорит открыть расширение; не выдаётся ложный статус ON. Все тесты/статические проверки проходят; реальные сайты после обновления требуют пользовательской проверки.

## Дополнение пользователя: полноэкранный режим
Запрос: «так же пофикси проблему с полноэкранным режимом, при открытии полноэкранного режима ничего не меняется».
Пользователь уточнил: «видео не разворачивается, остается поисковая строка браузера и внизу панель задач». В исходниках Chrome подтверждён режим fullscreen-within-tab для захваченных вкладок, оставляющий окно в прежнем состоянии; это соответствует описанному симптому.

План: обработать CaptureInfo.fullscreen при активной нормализации, развернуть именно окно активной вкладки через windows.update. Запомнить предыдущее состояние и восстановить только для окна, которое развернуло расширение; при выходе, завершении захвата или смене активной вкладки. Не закрывать и не перезапускать звук при переключении fullscreen. Не менять окна фоновых вкладок или уже вручную развёрнутые окна. Состояние владения хранится в storage.session и очищается при ручном выходе из fullscreen.

Проверки: вход/выход, нормальное/максимизированное/уже fullscreen окно, фоновые вкладки, завершение захвата, смена вкладки, перезапуск worker и ручное изменение состояния окна. Реальное окно Chrome в среде не управляется, поэтому полный runtime этого исправления проверяется пользователем после обновления.

Источник: https://raw.githubusercontent.com/chromium/chromium/main/chrome/browser/ui/exclusive_access/fullscreen_controller.cc (MaybeToggleFullscreenWithinTab).

## Delivery / Convergence
Требования автоподключения и уточнённый fullscreen-симптом покрыты реализацией. 39 тестов и статическая проверка проходят. Интерфейс проверен в браузере с имитацией Chrome API: переключатель, all/selected, домен из URL, удаление, ручная пауза и сохранение после перезагрузки страницы. Ошибок консоли нет. ZIP 0.2.0 проверен: 13 рабочих файлов, новые модули включены, preview/API mock исключены. Известное ограничение обязательного вызова расширения на новой вкладке не скрыто; проверка нативного Chrome и внешних сайтов остаётся пользовательской.
